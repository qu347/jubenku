# 上传平台持久化设计

## 目标

用户新增一次自定义上传平台后，平台名称永久保存到开发数据库。三位使用者在同一套系统中都能直接复用，不需要每次重新输入，也不依赖某条素材是否已经上传。

## 范围

- 新增上传平台数据表，预设平台与自定义平台使用同一套读取接口。
- 新增平台时立即持久化；名称去除首尾空格，并按 Unicode 规范化与不区分大小写规则防重复。
- 上传素材、编辑素材、素材筛选和题材定位图共同读取平台列表。
- 保留现有素材上的 `upload_platform` 字符串，避免迁移或改写历史素材。
- 暂不提供删除、重命名、排序和平台管理页面，避免破坏已有素材引用。

## 数据设计

新增 `UploadPlatform` 模型：

- `id`：UUID 主键。
- `name`：用户看到的平台名称，最长 60 个字符。
- `normalized_name`：NFKC、去首尾空格、casefold 后的唯一键。
- `is_system`：区分系统预设平台与用户自定义平台。
- `created_at`、`updated_at`、`deleted_at`：UTC 时间和软删除字段。

迁移只创建新表与索引，不修改 `materials.upload_platform`，不会影响现有素材。迁移会插入当前八个预设平台，并从现有非空素材平台中补录历史自定义平台。初始化数据脚本也会幂等补齐预设平台。

## 接口与分层

- `GET /api/upload-platforms`：返回全部有效平台，系统预设在前，自定义平台随后按名称排序。
- `POST /api/upload-platforms`：创建自定义平台；空白、超长返回 422，规范化重名返回 409。

接口使用 Pydantic 请求/响应模型，并经过 Repository 与 Service 层。异常继续使用项目现有统一响应格式。

## 前端行为

- `UploadPlatformSelect` 打开时加载持久化平台列表。
- 点击“添加自定义平台”并确认后，先调用创建接口；成功后立即加入下拉列表并自动选中。
- 上传抽屉、编辑抽屉和素材筛选共享 Pinia 平台 Store，避免重复请求与各组件状态不一致。
- 题材定位图的平台列表使用“持久化平台 + 当前有定位数据的平台”的并集；没有素材数据的平台仍可选择，图表显示空状态。
- API 暂时不可用时保留内置预设平台作为只读降级，不丢失用户当前表单内容。

## 错误处理

- 重名时提示“该平台已存在”，并选择已存在的平台。
- 网络或保存失败时保留输入框内容，提示用户重试，不伪装成已保存。
- 平台列表加载失败时仍显示预设平台，但自定义平台必须成功写入后才加入持久列表。

## 测试与验收

- 迁移可从 0008 升级、降级并再次升级。
- 后端覆盖列表、创建、空白、规范化重名、历史平台补录与幂等初始化。
- 前端先写失败测试，再覆盖新增后自动选中、重新打开仍显示、筛选共用列表、定位图包含无数据自定义平台和失败提示。
- 最终运行后端全量测试、前端类型检查、全量测试与生产构建。

验收标准：添加“星河阅读”一次后，关闭并重新打开上传窗口仍能直接选择；刷新页面、换另一台访问同一服务的电脑后也能看到；题材定位图的平台下拉框同步包含“星河阅读”。

## 明确不做

- 不删除或重命名平台。
- 不把素材改成外键引用平台，保持现有 API 与历史数据兼容。
- 不引入账号权限、审核流或多线程处理。
